1. 연결
----------------------------------------------------------------
 방식      : WebSocket, JSON 텍스트 메시지(UTF-8)
 주소      : ws://192.168.0.10:8765   (보드. 고정 IP 전까지는 앱 설정값으로 바꿔 넣는다)
 개발 중   : ws://<가짜 보드를 켠 노트북 IP>:8765   (device/mock_board.py)
 연결 유지 : 앱이 자녀 화면(5-1)에 들어오면 연결하고, 화면을 떠날 때까지 유지한다
 끊기면    : 3초마다 다시 연결한다. 연결이 안 되는 동안은 6-1(연결 안 됨) 화면
 공통 모양 : 모든 메시지는 "type" 항목을 가진 JSON 하나


2. 앱 → 디바이스 (2종)
----------------------------------------------------------------
 ID     type    함께 보내는 값   언제
 -----  ------  ---------------  ----------------------------------------
 AB-01  start   없음             5-1에서 "온기에게 말하기"를 눌렀을 때
 AB-02  stop    없음             듣는 중(5-2)이나 재생 중(5-5)에 멈춤을 눌렀을 때
                                 · 듣는 중(진짜 마이크): 취소가 아니라 "말 끝" — 들은 데까지 받아써서
                                   다음 단계(thinking)로 간다 (v1.2)
                                 · 그 밖(생각 중·공감·재생): 멈추고 idle

 예) {"type": "start"}
 - 진행 중에 start가 다시 오면 디바이스는 무시한다.
 - stop을 받으면 디바이스는 하던 일을 멈추고 idle을 보낸다.


3. 디바이스 → 앱 (8종)
----------------------------------------------------------------
 ID     type       함께 보내는 값                                    화면
 -----  ---------  ------------------------------------------------  --------
 AB-03  listening  없음                                              5-2
 AB-04  thinking   text: 받아쓴 글                                   5-3
 AB-05  empathy    text: 공감 한마디                                 5-4
                   has_message: 이어서 부모 메시지를 재생하면 true
                   author: "mom" / "dad" (has_message가 false면 null)
 AB-06  playing    situation_id: 1~12                                5-5
                   message_id: 메시지 번호
                   author: "mom" / "dad"
                   kind: "voice" / "text"
                   text: 글 메시지 내용. voice면 보드가 받아쓴 글(11/9),
                         무음 녹음이거나 받아쓰기 전이면 null
                   seconds: 메시지 재생 길이(초, 소수 1자리). 모르면 null (v1.2)
 AB-07  not_found  text: 받아주는 말                                 5-6
 AB-08  idle       없음                                              5-1
 AB-09  error      code: 오류 코드(5장)                              6-1 또는 안내
 AB-10  safety     text: 안전 응답(상담전화 1388 안내 포함)          5-6 모양

 예)
 {"type": "thinking", "text": "오늘 친구랑 싸웠어"}
 {"type": "empathy", "text": "속상한 일이 있었나 보다", "has_message": true, "author": "mom"}
 {"type": "playing", "situation_id": 4, "message_id": 1, "author": "mom", "kind": "voice", "text": null}
 {"type": "playing", "situation_id": 11, "message_id": 3, "author": "dad", "kind": "text",
  "text": "민준아, 상 받은 거 정말 축하해. 아빠는 네가 노력한 게 제일 자랑스러워."}
 {"type": "not_found", "text": "그런 날도 있지, 이야기해 줘서 고마워"}
 {"type": "error", "code": "D-002"}


4. 신호 순서 (경우별)
----------------------------------------------------------------
 모든 경우는 start로 시작해서 idle로 끝난다.

 ① 부모 메시지 재생    listening → thinking → empathy(has_message=true) → playing → idle
 ② 공감 한마디만       listening → thinking → empathy(has_message=false) → idle
 ③ 맞는 메시지 없음    listening → thinking → not_found → idle
 ④ 위기 표현           listening → thinking → safety → idle
 ⑤ 오류                listening → error → idle   (어느 단계에서든 error 뒤에는 idle)
 ⑥ 중간에 멈춤         ... → (앱 stop) → idle

 순서도

   [5-1 홈] --start--> listening [5-2 듣는 중]
                          |
                (말 끝 감지, 받아쓰기)
                          |-- 실패 --> error --> idle
                          v
                       thinking [5-3 생각하는 중, 받아쓴 글 표시]
                          |
              +-----------+------------+--------------+
              |           |            |              |
          위기 표현    상황+메시지   상황/기분만    해당 없음
              |           |            |              |
           safety      empathy      empathy       not_found
          [5-6 모양]  (true) [5-4] (false) [5-4]   [5-6]
              |           |            |              |
              |        playing         |              |
              |         [5-5]          |              |
              +-----------+------------+--------------+
                          v
                        idle [5-1 홈]

 - 화면은 신호가 올 때마다 바꾼다. 앱이 시간을 재서 넘기지 않는다.
 - 재생이 끝난 것은 idle로 안다. 재생 시간은 보내지 않는다.

6. 화면별 앱 동작
----------------------------------------------------------------
 5-4 공감 한마디  has_message가 false면 "이어서 메시지를 들려줄게" 문구를 숨긴다
 5-5 재생         text가 있으면 kind와 상관없이 글을 함께 보여 준다(11/9).
                  voice면 "목소리를 글로 옮겼어요" 같은 안내를 작게 붙인다. text가 null이면 파형만
                  author로 "엄마/아빠가 남긴 메시지"를 표시한다
 5-6 없음·안전    not_found와 safety는 같은 화면 모양. safety는 1388 안내 글을 그대로 보여 준다
 온기기록(5-7)    이 신호로 만들지 않는다. 서버 API-09로 조회한다


7. 가짜 보드 (DEV-05)
----------------------------------------------------------------
 파일 : device/mock_board.py, device/test_client.py
 설치 : pip install websockets
 실행 : python mock_board.py                     시연 문장 4개를 차례대로
        python mock_board.py --scenario safety   한 경우만 반복
        python mock_board.py --delay 0.5         신호 간격(초)
 시나리오 : normal / play_voice / play_text / empathy_only / not_found / safety / error
 확인 : python test_client.py ws://<노트북 IP>:8765
 개발 편의 : {"type":"start","scenario":"error"}처럼 start에 scenario를 넣으면
            그 경우로 한 번 진행한다. 가짜 보드에만 있는 기능이고 진짜 보드는 무시한다.

 시연용 고정 데이터 (공통지침 규칙 7)
   "오늘 친구랑 싸웠어"  → 상황 4  → 공감 + 엄마 녹음(message_id 1)
   "엄마 보고 싶어"      → 상황 10 → 공감 + 엄마 녹음(message_id 2)
   "나 오늘 상 받았어"   → 상황 11 → 공감 + 아빠 글(message_id 3, 온기 목소리)
   "배고파"              → 상황 없음 → 받아주는 말
