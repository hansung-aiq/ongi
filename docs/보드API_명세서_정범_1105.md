## 0. 한눈에

보드(온기 스피커)는 **30초마다** 서버에 아래 순서로 요청합니다.

```
1. API-14  POST /device/play-logs      아직 못 보낸 재생 기록 보내기
2. API-11  GET  /device/changes?since=  바뀐 부모 메시지 받기 (추가·수정·삭제)
3. API-12  GET  /device/audio/{id}      녹음 메시지면 녹음 파일 받기
4. API-13  POST /device/ack            "이 메시지들 받았어요" 알리기
```

- 서버가 꺼져 있어도 보드는 저장해 둔 메시지로 계속 돌아갑니다. 그러니 서버는 **이 4개만 정확히** 맞추면 됩니다.
- 로그인·토큰은 이번 시연 범위에서 **쓰지 않습니다.** (보드 1대, 가족 1개 기준)
- 주소: 개발 중에는 정범님 노트북에서 FastAPI를 `0.0.0.0:8000`으로 켜고, 보드 설정 `Config.SERVER_URL`을 `http://<노트북 IP>:8000`으로 바꿉니다.

## 1. 공통 규칙

| 항목 | 규칙 |
|---|---|
| 형식 | JSON, UTF-8. 응답 헤더 `Content-Type: application/json; charset=utf-8` |
| 시각 | `2026-11-05T21:30:00` 모양 (한국 시각, 시간대 표시 없음, 초까지) |
| 성공 | HTTP 200 |
| 실패 | HTTP 4xx/5xx + `{"error": "E-404", "message": "녹음이 없어요"}` |
| 메시지와 상황 | **상황 하나에 메시지 하나**. 같은 상황에 새로 등록하면 409 (API-04 쪽 규칙) |
| 삭제 | 메시지를 지울 때 DB에서 바로 지우지 말고 `deleted = true`로 바꾸고 `updated_at`을 지금 시각으로. 그래야 보드가 API-11로 "지워졌다"를 알 수 있음 |

메시지 한 개의 모양 (DB `messages` 테이블과 같음)

| 값 | 뜻 | 예 |
|---|---|---|
| `id` | 메시지 번호 (정수) | `5` |
| `situation_id` | 상황 번호 1~12 | `4` |
| `author` | `"mom"` / `"dad"` | `"mom"` |
| `kind` | `"voice"`(녹음) / `"text"`(글) | `"voice"` |
| `text` | 글 메시지 내용. voice면 `null` | `null` |
| `deleted` | 지워졌으면 `true` | `false` |
| `updated_at` | 마지막으로 바뀐 시각 (등록·수정·삭제할 때마다 지금 시각으로) | `"2026-11-05T21:29:10"` |

## 2. API-11 바뀐 메시지 받기

`GET /device/changes?since=2026-11-05T21:00:00`

- `updated_at`이 **`since` 이상**인 메시지를 `updated_at` 오름차순으로 줍니다 (v0.6). 지워진 메시지(`deleted=true`)도 줍니다. 같은 메시지가 한 번 더 와도 보드는 덮어쓰기라 괜찮습니다.
- `since`가 없으면 전부 줍니다. (보드가 처음 켜졌을 때는 `2000-01-01T00:00:00`을 보냄)
- `server_time`은 **서버의 지금 시각**입니다. 보드는 이 값을 다음 `since`로 쓰고, 보드 시계도 이걸로 맞춥니다(보드 시계가 1년 틀려 있음).

응답 200

```json
{
  "server_time": "2026-11-05T21:30:00",
  "messages": [
    {"id": 5, "situation_id": 4, "author": "mom", "kind": "voice", "text": null,
     "deleted": false, "updated_at": "2026-11-05T21:29:10"},
    {"id": 3, "situation_id": 11, "author": "dad", "kind": "text",
     "text": "민준아, 상 받은 거 정말 축하해.", "deleted": false, "updated_at": "2026-11-05T21:10:00"},
    {"id": 2, "situation_id": 10, "author": "mom", "kind": "voice", "text": null,
     "deleted": true, "updated_at": "2026-11-05T21:20:00"}
  ]
}
```

- 바뀐 게 없으면 `"messages": []`

## 3. API-12 녹음 파일 받기

`GET /device/audio/5`

- `kind`가 `voice`인 메시지의 녹음 파일을 **그대로** 줍니다 (부모 앱이 올린 m4a).
- 응답 200: 본문은 파일 바이트, 헤더 `Content-Type: audio/mp4`
- 글 메시지면 400 `{"error": "E-400", "message": "녹음 메시지가 아니에요"}`, 없거나 지워졌으면 404 `E-404` (v0.6)
- 보드는 받은 파일을 `files/audio/5.m4a`로 저장합니다. 변환은 보드가 합니다.

## 4. API-13 받았음 알리기

`POST /device/ack`

요청

```json
{"message_ids": [5, 3]}
```

응답 200

```json
{"acknowledged_ids": [5, 3]}
```

- 그 메시지들을 "보드에 전달됨"으로 표시합니다 (`delivered = true`, `updated_at`은 바꾸지 않음).
- 없는 id가 하나라도 있으면 아무것도 바꾸지 않고 404 (v0.6). 보드는 받은 메시지 id만 보내고, 지워진 메시지 id는 보내지 않습니다.
- 보드는 응답 내용은 보지 않고 2xx인지만 봅니다.

## 5. API-14 재생 기록 보내기

`POST /device/play-logs`

요청

```json
{"message_id": 5, "played_at": "2026-11-05T21:31:20"}
```

응답 201 (새 기록) / 200 (이미 있던 기록)

```json
{"id": 1, "message_id": 5, "played_at": "2026-11-05T21:31:20"}
```

- 아이가 말해서 부모 메시지가 재생될 때마다 1번씩 옵니다. DB `play_logs`에 한 줄씩 저장합니다.
- `played_at`은 보드가 서버 시각으로 맞춰서 보냅니다.
- 보드가 실패하면 다음 동기화 때 **같은 기록을 다시 보낼 수 있습니다.** 같은 `message_id` + `played_at`이 이미 있으면 새로 만들지 않고 기존 기록을 200으로 줍니다 (v0.6).
- 부모 앱의 "온기 기록"(API-09)은 이 표를 보여 줍니다. **아이가 한 말은 서버로 보내지 않습니다**(개인정보).

## 6. 시험하는 법

### 6-1. 가짜 서버로 모양 보기 (설치 없음)
```bash
cd ~/ongi && python3 device/mock_server.py          # 켜 두기
# 다른 탭
curl "http://127.0.0.1:8000/device/changes?since=2000-01-01T00:00:00"
curl -o a.m4a http://127.0.0.1:8000/device/audio/1
curl -X POST -H "Content-Type: application/json" -d '{"message_ids":[1,2]}' http://127.0.0.1:8000/device/ack
curl -X POST -H "Content-Type: application/json" -d '{"message_id":1,"played_at":"2026-11-05T21:31:20"}' http://127.0.0.1:8000/device/play-logs
```
정범님 서버에 같은 curl을 보내서 **응답 모양이 같으면 끝**입니다.

### 6-2. 진짜 보드와 붙이기 (11/11 통합 A)
1. 정범님 노트북과 보드를 같은 공유기에 연결
2. 지현이 보드 앱의 `Config.SERVER_URL`을 `http://<정범님 노트북 IP>:8000`으로 바꿔 빌드
3. 부모 앱(또는 curl)으로 메시지 등록 → 30초 안에 보드 기록에 `동기화: 메시지 n 받음`이 나오면 성공
